# Тесты адаптивности AskVK

Отдельный тестовый проект на `e2e` и `@e2e-dev/web` (Chromium). Зависимости сайта не меняются, тестовые скрипты не подключаются к HTML. Основной набор использует точные проверки браузера без `agent.*`: модель, подписка, API-ключи и вход в e2e для него не нужны. Отдельный ИИ-сценарий запускается только вручную, как описано ниже.

## Первый запуск

Нужны Node.js 24.8+ (или Node.js 22.22.3+ в ветке 22), npm и Python 3. Проверьте версии: `node --version`, `npm --version`, `python3 --version`.

Из корня репозитория:

```sh
cd tests/responsive
npm ci
npx @e2e-dev/web install chromium
npx e2e run
```

На Linux для установки системных зависимостей браузера вместо обычной установки используйте `npx @e2e-dev/web install chromium --with-deps`.

При последующих запусках достаточно:

```sh
cd tests/responsive
npx e2e run
```

Не нужно отдельно запускать сайт или останавливать сервер на порту 8000. Конфиг поднимает Python-сервер на свободном локальном порту, открывает Chromium и завершает процессы после прогона. Пути к `public/` вычисляются относительно конфига. Команды e2e выполняйте из этой папки.

## Что проверяется

Каждый из 10 сценариев выполняется на трёх размерах: `mobile-375` (375×812), `tablet-768` (768×1024), `desktop-1200` (1200×900). Всего 30 запусков.

- Все 7 страниц: `base`, `index`, `question`, `ask`, `login`, `signup`, `profile`.
- Нет горизонтального скролла страницы и переполнения внутри карточек, форм и групп кнопок.
- Ссылки, кнопки и поля не выходят за границы экрана.
- Логотип, поиск, кнопка вопроса и юзерблок не накладываются; поле поиска не пересекается с кнопкой.
- До 768 px сайдбар располагается ниже основного контента, от 768 px — справа.
- Поля помещаются в свои контейнеры и занимают их ширину на телефонах.
- При коротком контенте футер находится внизу окна. Для этой проверки высота увеличивается до 2400 px с сохранением ширины текущего target.
- Длинные значения в форме вопроса не растягивают страницу.
- Уже открытая страница вопроса перестраивается при переходах 1200 → 768 → 375 → 1200 px.

Проверки измеряют реальные размеры элементов с допуском 1 px на округление. Это проверки геометрии; они не оценивают эстетическое качество и не проверяют серверную фильтрацию или отправку статических форм. Для ручного осмотра сохраняются скриншоты страниц и заполненной формы. Сравнения с эталонными изображениями нет.

## Полезные команды

Только телефон:

```sh
npx e2e run --target mobile-375
```

Только страница вопроса:

```sh
npx e2e run --grep 'question.html:'
```

С видимым окном Chromium:

```sh
npx e2e run --headed
```

Список выбранных тестов без запуска браузера:

```sh
npx e2e list
```

Повторить только упавшие проверки:

```sh
npx e2e run --last-failed
```

## Результаты и диагностика

Успех — все 30 запусков прошли, код завершения 0. При ошибке читайте сообщение и путь к `trace.md`, который напечатал e2e.

Артефакты создаются внутри `tests/responsive/.e2e/`:

- `report.json` — результаты каждого теста, target и ошибки.
- `results/` — скриншоты; для упавших тестов — трассы `trace.md`.
- `logs/server.log` — вывод локального Python-сервера.

Папки `.e2e/` и `node_modules/` исключены из Git. Скриншоты относятся к последнему прогону: сохраняйте нужные артефакты перед следующим запуском.

Если Chromium не найден, повторите `npx @e2e-dev/web install chromium`. Если процесс запущен из Codex и получает `EPERM` при создании локального сервера или запуске браузера, требуется разрешение на запуск вне песочницы. Это ограничение окружения, а не ошибка верстки.

## Отдельный ИИ-тест: только ручной запуск

`manual/layout.ai.e2e.ts` — один сценарий, выполняемый на трёх размерах окна. ChatGPT оценивает шапку по скриншоту, сам открывает вопрос, проверяет его карточку, затем открывает форму вопроса и проверяет её видимую часть. Каждое действие `agent.act` подтверждается точным `expect`, визуальные оценки выполняются через `agent.assert` с `vision: 'only'`.

Конфиг `e2e.ai.config.ts` использует **`chatgpt('gpt-6-luna')`** через подписку ChatGPT. Схема подключения взята из [официальной документации e2e о подписках](https://e2e.tester.army/docs/subscriptions).

Из `tests/responsive/` один раз установите актуальные зависимости и войдите в ChatGPT:

```sh
npm ci
npx e2e login openai
npx e2e models openai
```

Завершите вход в открывшемся браузере. Если обычный вход недоступен, используйте `npx e2e login openai --device`. В списке моделей вашего аккаунта должна быть `gpt-6-luna`; тест не подменяет её другой моделью. API-ключ OpenAI не нужен.

Явно запустить ИИ-сценарий:

```sh
npm run test:ai
```

Или напрямую, только на телефоне:

```sh
npx e2e run --config e2e.ai.config.ts --target mobile-375
```

Посмотреть список без обращения к модели:

```sh
npm run test:ai:list
```

Обычные `npm test` и `npx e2e run` этот тест не включают: папка `manual/` находится вне основного glob `tests/**/*.e2e.ts`, а модель импортируется только отдельным конфигом. Добавлять ИИ-сценарий в автоматический запуск или CI не нужно.

ИИ-запуск использует лимиты подписки. Кэш отключён, поэтому каждый ручной прогон обращается к модели. Отчёт, скриншоты и трассы всех ИИ-проверок сохраняются отдельно в `.e2e/manual/`, чтобы не перезаписывать результаты обычного набора. Визуальная оценка модели вероятностная и дополняет точные проверки геометрии.

## Для Codex

Используй скилл `$e2e`. Работай из `tests/responsive/`, запускай существующий набор через `npx e2e run`, без отдельного сервера и AI-модели. При падении сначала читай указанную трассу и лог сервера; не добавляй задержки и не ослабляй проверки ради зелёного результата. Для новой страницы добавь запись в `pages` в `tests/responsive.e2e.ts`; общая проверка геометрии находится в `tests/layout.ts`. После исправления запускай упавшие тесты, а после изменения общей верстки — весь набор.

ИИ-сценарий запускай только по явному запросу пользователя через `npm run test:ai`. Не включай его в обычную проверку изменений. Его конфиг — `e2e.ai.config.ts`, модель — `gpt-6-luna` через подписку ChatGPT.
