# E2E-тесты Django-проекта AskVK

Отдельный тестовый проект на `e2e` и `@e2e-dev/web` (Chromium). Тесты открывают настоящие Django-маршруты, рендерят шаблоны и отправляют POST с CSRF. Папка `public/` больше не используется. Основной набор не обращается к ИИ и не требует подписки или API-ключей.

## Подготовка

Нужны Python 3.14, Python-зависимости из корневого `requirements.txt`, Node.js 24.8+ (или 22.22.3+ в ветке 22) и npm.

Из корня репозитория, если Python-окружение ещё не подготовлено:

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Затем:

```sh
cd tests/responsive
npm ci
npx @e2e-dev/web install chromium
npx e2e run
```

На Linux системные зависимости браузера устанавливаются через `npx @e2e-dev/web install chromium --with-deps`.

При последующих запусках достаточно `npx e2e run` из этой папки. Серверы завершаются после прогона. В Codex для открытия локальных портов и запуска Chromium может понадобиться разрешение на запуск вне песочницы.

## Как запускается приложение

По умолчанию конфиг выбирает Python из корневой `.venv` (в Windows — `.venv/Scripts/python.exe`), иначе использует `python3.14`. Можно задать другой интерпретатор:

```sh
E2E_PYTHON=/absolute/path/to/python npx e2e run
```

`scripts/serve_django.py` импортирует настройки `AskVK`, включает `DEBUG` для раздачи исходной статики и запускает `runserver` без autoreload на свободном локальном порту. Для каждого сервера создаётся отдельная временная SQLite-база, применяются миграции, генерируется тестовый секретный ключ; `media` тоже располагается во временной папке.

Тестовые настройки действуют только внутри процесса. `.env` не читается, настройки на диске не меняются, данные PostgreSQL проекта не используются. Это браузерная проверка текущих view с данными-заглушками, а не проверка совместимости PostgreSQL или авторизации.

Чтобы проверить уже работающий Django или Docker/nginx, укажите адрес:

```sh
E2E_BASE_URL=http://localhost npx e2e run
# Либо локальный runserver:
E2E_BASE_URL=http://127.0.0.1:8000 npx e2e run
```

В этом режиме тесты не запускают сервер, не меняют его настройки и не выполняют миграции. Сервер и его базу нужно подготовить самостоятельно по корневому README. Проверки рассчитаны на текущие тестовые вопросы с id 1–3 и текущее поведение форм без сохранения в БД.

## Покрытие

18 сценариев запускаются на трёх размерах: `mobile-375` (375×812), `tablet-768` (768×1024), `desktop-1200` (1200×900). Всего **54 проверки**.

- Шесть страниц: `/`, `/question/1/`, `/ask/`, `/login/`, `/signup/`, `/profile/`.
- Нет горизонтального скролла и переполнения карточек, форм и групп кнопок.
- Шапка остаётся в одну строку, поиск и элементы управления не перекрываются.
- До 768 px сайдбар находится под основной колонкой, от 768 px — справа.
- Поля помещаются в контейнеры и растягиваются по ширине на телефонах.
- Футер при коротком контенте находится внизу окна: проверяется `/login/` с высотой окна 2400 px.
- Длинные значения полей не растягивают форму вопроса.
- Открытая страница вопроса перестраивается при ширинах 1200 → 992 → 991 → 768 → 546 → 375 → 1200 px.
- Меню Bootstrap открывается, закрывается по Escape и позволяет перейти на `/ask/`.
- Регистрация открывается с пустыми email и никнеймом.
- CSS, JS и favicon доступны через `/static/` с корректными типами содержимого.
- Ссылка из списка открывает выбранный вопрос №2 и его ответы.
- Пагинатор вопросов и ответов скрыт, если страница одна.
- Неизвестный вопрос и неверный `page` возвращают HTTP 404.
- Гость видит ссылку на вход вместо формы ответа.
- Реальный POST с четырьмя тегами показывает серверную ошибку и сохраняет введённые поля.
- Валидный POST проходит CSRF и валидацию; отображается сообщение о проверке данных без заявления о публикации.

Геометрия проверяется с допуском 1 px на округление. Скриншоты сохраняются для ручного осмотра, сравнения с эталонными изображениями нет. Основной набор не проверяет реальное сохранение данных, загрузку аватаров, вход в аккаунт или ещё не реализованную фильтрацию.

## Команды

```sh
# Весь обычный набор
npx e2e run

# Только телефон
npx e2e run --target mobile-375

# Только страница вопроса
npx e2e run --grep '/question/1/:'

# Видимое окно Chromium
npx e2e run --headed

# Список без запуска браузера
npx e2e list

# Повторить упавшие проверки
npx e2e run --last-failed
```

Альтернатива полному запуску — `npm test`.

## Отчёты

Результаты обычного набора находятся в `tests/responsive/.e2e/`:

- `report.json` — результаты тестов и ошибки.
- `results/` — скриншоты, а при падении также `trace.md` с последовательностью шагов.
- `logs/server-mobile-375.log`, `server-tablet-768.log`, `server-desktop-1200.log` — вывод автоматически запущенных Django-серверов.

Папки `.e2e/` и `node_modules/` исключены из Git. Следующий прогон обновляет результаты: сохраняйте нужные скриншоты перед ним. При ошибке сначала читайте путь к `trace.md` из вывода e2e и лог соответствующего Django-сервера.

## Отдельный ИИ-тест: только вручную

`manual/layout.ai.e2e.ts` — один сценарий на каждом из трёх размеров. ChatGPT оценивает шапку по скриншоту, открывает вопрос, оценивает карточку, затем открывает форму нового вопроса и оценивает её видимую часть. Действия `agent.act` подтверждаются точными проверками, визуальные оценки выполняются через `agent.assert` с `vision: 'only'`.

Конфиг `e2e.ai.config.ts` использует **`chatgpt('gpt-6-luna')`** через подписку ChatGPT, согласно [документации e2e о подписках](https://e2e.tester.army/docs/subscriptions). Для первого запуска:

```sh
npx e2e login openai
npx e2e models openai
npm run test:ai
```

Модель `gpt-6-luna` должна быть доступна вашему аккаунту. API-ключ не нужен. При проблемах с обычным входом можно использовать `npx e2e login openai --device`.

```sh
# ИИ только на телефоне
npx e2e run --config e2e.ai.config.ts --target mobile-375

# Посмотреть список без вызова модели
npm run test:ai:list
```

Обычные `npm test` и `npx e2e run` не включают папку `manual/` и не загружают ИИ-конфиг. Модель вызывается только при отдельном ручном запуске; кэш отключён. Эти вызовы используют лимиты подписки. Результаты сохраняются отдельно в `.e2e/manual/`. Визуальная оценка ИИ дополняет точную проверку геометрии.

ИИ-конфиг поддерживает те же `E2E_PYTHON` и `E2E_BASE_URL`, что основной.

## Для Codex

Используй скилл `$e2e`. Запускай `npx e2e run` из `tests/responsive/`: основной конфиг сам поднимает Django с временной SQLite-базой. Не запускай статический сервер, не подменяй реальные HTTP-ответы и не добавляй задержки. При изменении формы, маршрута или шаблона обновляй соответствующие ожидания, а при падении сначала изучай трассу и лог сервера.

ИИ-сценарий запускай только по отдельному явному запросу пользователя. Не включай его в автоматический прогон и CI.
